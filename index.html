Collective Forensics

Scale-up domain SU-01 · MoE dispatch all-to-all

When a collective runs slow, name the xPU, port or expert that cost the time, and prove it.

Every slow all-to-all is replayed against three counterfactuals: re-time the latest sender, rebalance the hottest destination, restore the slowest port. Start times come from each NIC's PTP clock, so every saving carries a ±2ε interval from the clock's error bound. A cause is named only when its whole interval wins; otherwise the verdict is an honest "clock too loose to tell".

How the verdict is made

  1. Fluid replay. The switch's byte counters give the full xPU-to-xPU traffic matrix; port rates come from link state. Completion of the all-to-all is computed exactly for an output-queued single-hop fabric (last-bit departure per destination port).
  2. Three counterfactuals. Re-time the latest-starting senders to the median start, rebalance the hottest destination to the median load, restore the slowest port. Each saving is "how much sooner the collective would have finished".
  3. Clock-error intervals. Completion is non-decreasing and 1-Lipschitz in every start time, so a saving computed from starts that are each off by at most ε is within ±2ε of the true saving. No distributional assumption.
  4. Verdict. Name a cause only if its lower bound clears and beats every other upper bound. Below threshold everywhere is "no fault". Anything else abstains.
